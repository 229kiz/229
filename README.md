# Aeration Data Check

曝气分区的数据接入与质量诊断助手。一个无构建步骤、无第三方前端依赖的本地网页 demo。

**回答的问题：一份曝气监测数据中哪些片段需要检查，是否适合继续进入建模验证？**

## 立即运行

双击 `index.html` 即可使用，不需要安装软件、模型账户或联网。

如需通过本地服务器访问，在此目录执行 `python -m http.server 8765 --bind 127.0.0.1`，浏览器访问 `http://127.0.0.1:8765`。

首次打开自动显示问题数据。点击「演示指引」获取 90 秒讲解步骤。

## 范围与案例

以 Daneshgar et al. (2024) 对荷兰 Eindhoven WRRF 数字孪生数据流程的研究为案例背景。内置数据由本项目确定性生成，**不是埃因霍温实测数据，不是该厂模型复现**。默认阈值也不是该厂运行限值。

当前版本聚焦 CSV 导入、可解释规则、人工核查及可追溯导出。它是数字孪生的数据准备组件，不是完整数字孪生，不预测水质，不控制设备。

为使课堂演示可离线运行，**v0.1 不集成 Astra，也不会模拟一次真实模型调用**。Astra 的测点描述理解及结果解释可在后续版本集成；确定性规则检查仍应独立于大模型运行。未来模型功能需要模型访问权限，不能在前端硬编码密钥。

## 功能

- CSV 导入：UTF-8（含 BOM）、逗号／分号／制表符、带引号字段，最多 20,000 行、8 MB。
- 手动字段映射：时间、溶解氧、供气量、温度。时间必填，至少映射一个数值字段。
- 单位转换：DO 的 mg/L 或 µg/L；供气 m³/h 或 m³/min；温度 °C 或 °F。转换仅用于分析，原始数据保留。
- 规则：缺测／非有限数值、无效时间、重复时间、逆序、采样断档、配置范围越界、持续卡值、DO 变化速率。
- 趋势图：缺测和时间断档处断线；点击事件高亮时间片段并展示原始 CSV 记录。
- 人工结论：待确认、数据异常、真实工况变化，附核查依据。
- 导出：带标记 CSV、独立 HTML 报告、结构化 JSON 报告。
- 所有数据仅存在浏览器内存；不联网、不上传。刷新或切换数据后不保留人工核查，请先导出。

## CSV 示例

```csv
timestamp,DO_mg_L,airflow_m3_h,temperature_C
2026-06-01T00:00:00+02:00,2.10,650,19.2
2026-06-01T00:05:00+02:00,2.15,660,19.3
```

时间支持 ISO 8601，`T` 可换为空格。建议带时区。无时区时间按本机时区解释，图表也按本机时区显示，JSON 保留 UTC ISO 时间。Excel 数字日期及纯日期不自动猜测。

通过网页「下载模拟数据 CSV」可获得完整测试样例。问题数据包含缺测、DO 卡值、DO 尖峰、负供气、温度越界、采样断档及重复时间。正常对照使用同一生成函数且不注入这些故障。正常对照并不代表经校准的真实过程。

## 如何解读诊断

字段完整率 = 已映射数值字段中有限数值个数 / 期望数值个数。越界数值仍计为完整，因此完整率不是准确率，也不是建模可用率。

标记记录数按原始行去重；同一条记录可能触发多个事件。断档事件标记两端现有记录，不生成不存在的记录。

卡值检查要求至少三点、持续时间达到配置值、相邻间隔不超过中位采样间隔的 1.5 倍，并以 0.000001 为相同读数容差。它不能区分稳定工况与仪表故障，也不能可靠检测缓慢漂移。

DO 突变阈值为每分钟绝对变化量，仅在相邻有效时间且无明显断档时计算。恢复尖峰可能产生两个事件。这些是检查提示，不是自动故障诊断。

人工标记不会自动改值或取消原始规则。即使标为真实工况，缺测、重复时间等硬性问题仍提示需要处理后复检。规则未触发也不意味着满足所有模型需求；缺少 DO 或数据太短会明确提示。

## 验证

有 Node.js 时在项目目录执行：

```sh
node tests/core.test.cjs
```

覆盖模拟故障、正常对照、零值、时区、CSV 引号、输入单位、时间断档、核查结论及缺测断线所需原始空值保留。网页还需人工测试上传、事件定位和导出。

## 开发与后续方向

`core.js`：独立纯函数规则引擎，可在浏览器和 Node 中复用。

`app.js`：字段映射、SVG 趋势、核查及导出。

`style.css`、`index.html`：响应式页面，无外部字体或 CDN。

欢迎补充不同水厂数据适配器、带标签的公开测试集和可解释规则。贡献时请注明数据来源及授权，勿提交真实水厂的未授权监测数据。核查真实数据时应将人为注入异常、真实异常标签与规则预测分别保留。

第一版不做自动补全、仪表故障确诊、跨变量因果推断或实际控制。后续 Astra 功能应解释结构化检测证据，不应替代确定性检测规则或擅自修复测量数据。
